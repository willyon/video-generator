## 1. 总评

以「成熟的本地个人视频生成应用」为尺，本项目当前处于：

**核心创作管线已打通的进阶原型 / 可用工作室骨架（约 7 成）。**

更细一点：

| 维度 | 成熟度 | 说明 |
| --- | --- | --- |
| 产品范围与边界 | **高** | 本地、单用户、短片闭环；刻意排除多人/计费/分布式，边界清晰 |
| 主工作流完整性 | **高** | 主题 → 分镜 → 冻结 → 生成 → 校验 → 审核 → 无声母版 → 声音 → 混音成片，主路径齐全 |
| 架构与契约设计 | **高** | Provider 适配、冻结规格、版本不可变、能力约束、任务可取消/可续跑，方向正确 |
| 真实模型可用性 | **中低** | Mock 端到端扎实；云端/Comfy/音频 HTTP 是通用合同，尚未用真实供应商打穿 |
| 产品体验与工程包装 | **中** | 单页可用；缺向导式流程、桌面安装包、磁盘治理、时间线深度编辑 |
| 成片质量上限 | **中** | 技术校验有；镜头间连续性、转场、对口型、自动避让等尚未进入产品层 |

**一句话：**  
框架流程**合理、科学、对当前声明范围大体完整**；距离「每天能放心用真实模型出片的成熟本地应用」还差：**真实 Provider 打通验证、桌面化交付、镜头连续性与时间线体验、资源生命周期管理**。

### 1.1 产品意图更新（2026-09-25）

产品目标已明确为 **兼顾**：

1. **单个短视频** — 现有管线；旁白/对白挂在镜头上即可，不强制独立剧本页。  
2. **系列视频** — 未来在管线之上增加 Series、共享资产库与可编辑剧本，再落到现有 Video 成片流程。

详见 [`WORKFLOW.md`](./WORKFLOW.md)。**系列与剧本排在 Gate D**；在真实 Provider（Gate A）打通之前不要开工，以免双栈分叉。

## 3. 当前已做到的能力（对照成熟标准）

### 3.1 产品定位（优秀）

- 本地优先：数据在 SQLite，成片在 `outputs/`，密钥不进仓库。
- 范围克制：不做多人协作、计费、云存储、分布式队列——符合个人工具。
- 工作流文档与代码约束一致（先完成一条用户路径，再叠媒体层；不暴露未实现能力）。

### 3.2 主创作闭环（完整）

与 `docs/WORKFLOW.md` 的 12 步基本对齐，且前后端均已落地：

1. 主题 / 时长 / 画幅 / 语言 / Provider  
2. 项目级视觉与声音方向  
3. 脚本与分镜规划（OpenRouter 或离线规则）  
4. 镜头增删改排、生成模式、参考素材  
5. 冻结并编译可追溯 `generation_spec`  
6. 镜头版本化生成（旧版本保留）  
7. FFprobe 技术校验（时长、分辨率）  
8. 人工审核通过 / 驳回，可单镜重生  
9. 无声母版拼接 + 可选 SRT  
10. 旁白 / 对白 / 音乐 / 音效时间线  
11. 音频版本选择与预览  
12. 混音导出最终 MP4（带音轨）

### 3.3 架构设计亮点（科学）

| 设计点 | 评价 |
| --- | --- |
| **冻结计划（freeze）** | 编辑与生成分界清晰；冻结时校验时长总和、Provider 能力、模式所需素材 |
| **Prompt 编译** | 项目方向按字段分段编译进镜头规格，避免「整段方向糊进 prompt」；可预览冻结指令 |
| **能力矩阵（capabilities）** | 时长 range/options、画幅、模式与必填素材分离；规划时按 Provider 拆分镜时长 |
| **Provider 适配层** | mock / cloud-http / comfyui（视频）；mock / cloud-http / local-http（音频）；业务层不绑死某一厂商 |
| **版本不可变** | `shot_versions` / `audio_versions`；选择有效版本后重组装 |
| **任务生命周期** | queued → running → done/error/cancelled；进程重启标记 interrupted；可 resume |
| **媒体管线** | FFmpeg 拼接、字幕、混音；技术校验再选版本 |
| **隐式下游失效** | 改分镜会清成片路径与音频选中态，避免脏状态 |

### 3.4 数据模型（够用且清晰）

核心实体齐全：`videos`、`video_shots`、`shot_versions`、`video_assets`、`audio_segments`、`audio_versions`、`generation_jobs`、`settings`。

状态语义基本自洽：`draft → ready → generating → review → approved → audio → complete`（含 `partial` / `error`）。

### 3.5 测试与可验证性（良好）

- Smoke：离线规划时长合拢。  
- Integration：增删排镜头、缺素材拒绝冻结、规格编译、生成、审核、版本切换、中断续跑、仅合成续跑、音频计划、混音与音轨探测。  
- 本报告审验时 `npm run check` **通过**。

## 4. 流程设计是否合理 / 科学 / 完整？

### 4.1 结论

| 问题 | 结论 |
| --- | --- |
| 是否合理？ | **是。** 先规划再烧视频额度、先画面审核再声音、先无声母版再混音，符合生成式短视频成本与可控性。 |
| 是否科学？ | **大体是。** 冻结规格、版本、技术校验、能力约束、适配器隔离，是正确的「应用层职责」划分（模型可用性外置）。 |
| 是否完整？ | **对「主题→十余秒可审短片」声明范围：主路径完整；对「成熟本地个人工作室」：管线完整度约 80%，产品化与质量层仍有缺口。** |

### 4.2 流程合理性示意

```text
配置与方向
    ↓
规划分镜 ──(可编辑)──→ 冻结规格
    ↓                      ↓
  解冻 ←───────────── 生成镜头版本
                           ↓
                     技术校验 → 选版本 → 人工审核
                           ↓
                     无声母版 + SRT
                           ↓
                     声音计划 / 生成 / 选版本
                           ↓
                     混音 → 最终 MP4
```

该闭环与成熟短视频生成工具的共性一致：**Plan → Spec → Generate → Validate → Approve → Assemble → Audio → Mix**。没有把「模型打分」硬塞进主路径，对本地个人工具是务实选择。

### 4.3 流程上仍不完整 / 偏弱的环节

1. **镜头间连续性**：`continuity` 多为提示词元数据，缺少「上一镜尾帧 → 下一镜首帧」自动链、角色库跨项目复用。  
2. **合成质量**：`concat` 硬切，无转场、无色彩匹配、无镜头级音画同步微调。  
3. **审核门闩与声音入口**：声音区依赖「全部镜头 approved」；合理，但审核 UX 仍是列表按钮，非明确阶段向导。  
4. **真实 Provider 门闩**（文档已写明）：通用 HTTP/Comfy 合同存在，**未证明**对具体模型稳定出片。  
5. **失败粒度**：单镜失败会打断整批任务（可 resume），并行与「失败跳过继续」策略偏简。

## 5. 与「成熟本地个人应用」的差距清单

按优先级分组（P0 = 要日常可用必须补；P1 = 体验与质量；P2 = 锦上添花）。

### P0 — 日常可用门槛

| 缺口 | 现状 | 建议方向 |
| --- | --- | --- |
| 真实视频 Provider 打通 | 通用 cloud-http / Comfy 占位 | 选定 1–2 个真实模型，在适配器内做 payload 映射并写验收用例 |
| 真实音频 / TTS | 合同存在；mock 为人声静音 / 正弦 | 接本地或云端 TTS，验证旁白时长与口型无关场景下的对齐策略 |
| 桌面交付 | 需 Node + 手启 API/Web + 本机 FFmpeg | Electron / Tauri 或至少一键启动脚本 + FFmpeg 探测与安装提示 |
| 磁盘与删除语义 | 删项目/镜头不清理成片；UI 已提示保留 | 可选「删库并清文件」；孤儿版本清理策略 |

### P1 — 体验与成片质量

| 缺口 | 现状 | 建议方向 |
| --- | --- | --- |
| 分阶段向导 UI | 单页长滚动，阶段靠状态字 | 按「规划 / 生成 / 审核 / 声音 / 导出」分步或强引导 |
| 前端结构 | 几乎全部在 `App.vue` | 按阶段拆组件；路由或步骤状态机 |
| 时间线编辑 | 音频有简陋标尺；无波形、无拖拽吸附 | 最小可用：拖拽起止、重叠提示、人声避让预设 |
| 跨镜一致性 | 项目参考图 + prompt | 首尾帧链、角色参考强制注入、可选 identity 锁 |
| 合成选项 | 固定 libx264 concat | 码率/分辨率预设；可选烧录字幕 |
| 任务队列 | 进程内 `queueMicrotask` | 对本地单用户可接受；可加启动时恢复面板与并发上限说明 |

### P2 — 进阶能力（非必做）

- 口型同步、对白驱动画面  
- 镜头转场 / 调色 / BGM 自动 ducking  
- 项目模板、风格预设库  
- 语义质量评分（文档已说明应保持人工）  
- 多人、云同步、计费（与当前定位冲突，保持不做）

## 6. 分模块审验摘要

### 6.1 API 与服务层

**优点：** 路由与领域操作一一对应；错误有明确中文业务提示；冻结/审核/混音前置条件清楚。  

**风险：**

- Job 取消依赖内存中的 `AbortController`；重启后只能 resume，不能对「已发出的远端任务」做真正撤销（本地工具可接受，需文档化）。  
- `deleteVideo` 仅删库记录，成片目录可能残留。  
- Schema 用 `ensureColumn` + `DROP COLUMN` 就地迁移，对个人库够用，但缺少版本号迁移表，长期演进会变脆。

### 6.2 Provider 层

**优点：** 适配器边界清晰；Comfy 支持占位符与参考图上传；cloud 支持轮询与多字段兼容。  

**风险：** 字段兼容靠「猜多个 JSON 键」；vendor 差异未沉淀为可测契约。Mock 掩盖了真实失败模式（超时、内容审核、分辨率漂移）。

### 6.3 媒体层

**优点：** 校验失败不进入 valid；混音后检查音轨；字幕按时长轴写 SRT。  

**风险：** 时长容差固定（视频 0.4s / 音频 0.5s）；硬拼接对真实模型输出抖动敏感；无重新编码对齐帧率策略说明。

### 6.4 前端

**优点：** 冻结态禁用编辑、进度条、版本选择、声音时间线入口、设置页覆盖三类 Provider。  

**短板：** 无步骤导航；信息密度高；设置页偏工程化；缺少「下一步该做什么」的产品提示。

### 6.5 工程化

**优点：** npm workspaces、`check` 脚本、环境变量可隔离测试数据目录。  

**短板：** 无正式单元测试框架；无 CI 配置；无类型系统；无发行版打包。

## 8. 建议演进路线（短片 + 未来系列）

与 [`WORKFLOW.md`](./WORKFLOW.md) 的 Gates 对齐。

### Gate A — 真实可用性（**下一步应做**）

1. 固定一个云端视频模型 **或** 一个本地 Comfy 工作流，写「合同 → 适配 → 样片」验收。  
2. 固定一个 TTS（旁白/对白）HTTP，验证时长与混音。  
3. 把成功样片路径写进 `docs/`（不含密钥）。

### Gate B — 个人日用

1. 一键启动 + FFmpeg 健康检查。  
2. 删除项目可选清磁盘；设置页磁盘占用提示。  
3. UI 按短片五阶段收束信息架构。

### Gate C — 短片成片质量

1. 相邻镜头首尾帧衔接选项。  
2. 混音 ducking 与简单转场。  
3. 导出预设（横/竖、码率）。

### Gate D — 系列 + 剧本（产品意图已定，实现靠后）

1. `Series` + 跨集角色/风格资产库。  
2. 剧本文档 + 显式「应用到本集 / 刷新分镜」同步。  
3. 从单集剧本物化为现有 Video 项目，不复制生成栈。

不要并行做：现在就开 Series UI、非线性剪辑器、语义自动评分平台、多人协作——会稀释当前清晰的管线优势，并在真实出片未验证时扩大表面积。

| 判断项 | 结论 |

| 是否已经是「能跑通的本地短视频生成应用」？ | **是**（尤其 mock 路径经集成测试证明）。 |
